# A-eye iOS App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A camera-first SwiftUI iPhone app: launch onto the rear camera, swipe a ring of helper modes (server v2
packs), tap to start a call on `/ws2` that sends frames, speaks, listens and draws the server's ops over the view.

**Architecture:** All protocol and state logic lives in a pure Swift package `ios/AEyeCore` (no UIKit, runs
`swift test` on macOS). The app target `ios/AEye` is a thin shell: camera, speech, socket and SwiftUI views that
feed events into `CallState.reduce` and render the result. Behaviour mirrors `client-web/agent.js` + `draw.js`.

**Tech Stack:** Swift 6 / SwiftUI, iOS 17+, Apple frameworks only (AVFoundation, Speech, CoreImage,
URLSessionWebSocketTask), XCTest. Xcode 27.1.

**Spec:** `docs/superpowers/specs/2026-10-23-ios-app-design.md`

## Global Constraints

- Contract is `contracts/schema.json` v2. Every message has `"v": 2`; `additionalProperties:false`, so never send a
  key the schema doesn't list and never encode `nil` as `null` (omit it).
- `hello` always sends `client:"ios"`, `tts:"browser"`; `board_id:"demo-b650"` only for `pc_build`.
- `frame` has no `orientation` key. Long side ≤ 640 px, JPEG quality 0.7, one per 1.0 s, skip while a send is in
  flight. Reconnect 2.0 s after a close.
- Role colours: target `#3DDC97`, info `#9EB6FF`, warn `#FF8A3D`, ok `#4C9AFF` (unknown → info). Draw-in 250 ms,
  fade 350 ms.
- No third-party packages. No API keys in the app. Frames, photos and audio are never written to disk or logged.
- Speech recognition: `requiresOnDeviceRecognition = true`; if unavailable, typed input.
- Copy never implies the app is safe for mains, gas or PSU internals, or that it's a certified/medical tool.
- Portrait only.
- The agent sandbox cannot run `xcodebuild`, the simulator or (likely) `git`. Steps marked **[you]** are run by
  the user on their Mac/iPhone. Try `swift test` from the agent; if the sandbox blocks it, hand it to the user.
- Only `ios/`, `docs/superpowers/` and `RESULT.md` are edited. Anything else (Makefile, root `.gitignore`) needs
  its owner.

## Review Focus

1. **Wi-Fi blip / server restart mid-call** → socket closes, app shows "Reconnecting…", re-sends `hello` after
   2 s, clears the overlay, and in PC Build shows **Power is off** again. Pinned in Task 4
   (`testReconnectResetsPowerOffAndDrawing`).
2. **Server sends a type the app doesn't know** (`metrics`, `track`, `audio`) or a malformed frame → ignored, no
   crash, state unchanged. Pinned in Task 2 (`testUnknownTypeIsIgnored`, `testGarbageIsNil`) and Task 4
   (`testIgnoredMessageLeavesStateUnchanged`).
3. **Camera, mic or speech permission denied** → no black screen: Camera screen explains and links to Settings;
   a call falls back to typed input. Pinned in Task 4 (`testInputModeFallsBackToTyped`) and device-checked in
   Tasks 5 and 8.
4. **The app's own TTS heard by the mic** → must not barge-in on itself. Pinned in Task 4
   (`testEchoOfSpokenLineIsNotBargeIn`).
5. **Frame aspect ≠ screen aspect** (sensor 16:9, phone ~19.5:9) → boxes land on the object, not shifted. Pinned
   in Task 3 (`testCoverTransformCentresPortraitFrame`) and Task 1 (`testFrameSizeKeepsAspect`).
